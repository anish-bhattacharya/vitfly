# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: roslaunch-kills-ros-master — When `render:=True` is passed to `visionenv_sim.launch`, Unity is launched as a ROS node (`flight_render-3`). When Unity exits or crashes, roslaunch kills the entire ROS master, severing all node connections. `run_competition.py` loses ROS and `img_callback` never fires. Fix: pass `render:=False` to roslaunch and launch Unity externally BEFORE roslaunch.

- [ ] CONSTRAINT: stale-summary-yaml — `launch_mamba_evaluation.bash` appends `envtest/ros/summary.yaml` to `evaluation.yaml` after each rollout. If a previous run left stale data in `summary.yaml`, all rollouts get identical data. Always `echo "" > envtest/ros/summary.yaml` before starting a new eval run.

- [ ] CONSTRAINT: ROS_IP_ALIAS — `launch_mamba_evaluation.bash` hardcodes `192.168.233.250`. This IP disappears on every `wsl --shutdown`. Run `ip addr add 192.168.233.250/32 dev lo` before ANY simulation attempt.

**Do not proceed until all boxes are checked.**
